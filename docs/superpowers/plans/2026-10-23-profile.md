# Profile Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Profile tab the plant detail screen's look and add avatar photo, in-place name editing, password change and account deletion.

**Architecture:** Shared gets the password rule and the user's avatar fields. The API adds avatar routes (same storage and validation as plant photos), a password change that keeps the calling device's session, and account deletion that removes stored files. The app extracts the plant detail header into a shared hero component, adds account actions to `AuthProvider`, and rebuilds Profile from small components on the existing `BottomSheet`.

**Tech Stack:** zod 4 (`packages/shared`), Fastify 5 + Prisma 7.10 + bcryptjs + Vitest (`api`), Expo SDK 57 + Jest (`app`).

**Spec:** `docs/superpowers/specs/2026-10-23-profile-design.md`

## Global Constraints

- Branch `profile` (checked out). No merge or PR without Arthur.
- Name: trimmed, 1 to 60 characters. Password (sign-up and new password): 8 to 128 characters and at most 72 bytes in UTF-8.
- Delete confirmation word, exact after trimming, case-sensitive: `DELETE` in English, `EXCLUIR` in Portuguese.
- Changing the password keeps the calling device signed in and revokes every other refresh token of the user.
- Avatar upload: same type detection and 5 MB cap as plant photos; served only to its owner.
- Every sheet is the existing `app/src/components/BottomSheet.tsx`; the toast is the plant detail "Saved ✓" pattern. No new modal or animation.
- Every new string in `app/src/i18n/locales/en.ts` and `pt-BR.ts`, Portuguese written naturally.
- New app files are added to the strict typed-rules file list in `app/eslint.config.js`. Lint forbids `any`, type assertions and non-null assertions.
- Jest: wait for an element to disappear with `.not.toBeOnTheScreen()` (never `toBeNull()` inside `waitFor`), with `{ timeout: 10000 }` for sheet closes and a per-test timeout that leaves margin; CI is a slower Linux runner.
- Run `npm run db:test:prepare -w @plantcare/api` before API tests; `npm run db:migrate -w @plantcare/api` after the migration.

## Review Focus

1. A wrong current password in Change password shows an error in the sheet and changes nothing: no sign-out, sessions intact (Tasks 3 and 5 tests).
2. After a password change, this device's refresh token still refreshes and another device's token is rejected (Task 3 test).
3. Deleting an account removes its plant photos and avatar files from storage and its rows from the DB; logging in again fails (Task 3 test).
4. The delete confirmation: `delete` (lowercase) keeps Confirm disabled, ` DELETE ` (spaces) enables it, and in Portuguese only `EXCLUIR` works (Task 5 test).
5. Name editing: Cancel restores the stored name; a blank or 61-character name keeps Save disabled (Task 5 test).

### Task 3: API password change and account deletion

**Files:**
- Modify: `api/src/me/routes.ts`, `api/src/auth/service.ts` (or a new `api/src/me/service.ts`), tests `api/src/me/routes.test.ts`

**Interfaces:**
- Consumes: Task 1 `changePasswordSchema`; Task 2 avatar storage key on the user; `hashRefreshToken`, `BCRYPT_COST`, the auth rate limit config.
- Produces:
  - `POST /me/password` (authenticated, rate limited like login), body `changePasswordSchema` → 204. 400 `validation_error` for a bad new password, 403 `wrong_password` for a wrong current one, 409 `no_password` for an account without one. On success: new bcrypt hash; every refresh token of the user deleted except the one whose hash matches `refreshToken` (if that token is not the user's, still 204 and all are revoked).
  - `DELETE /me` (authenticated) → 204: collect the user's plant `photoPath`s and `avatarPath`, delete the user (plants and refresh tokens cascade), then remove those files from storage (ignore a missing file).
